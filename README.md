# ios-ai-core

앱이 아니라 **에이전트 실행 평면**이다. 화면도, 저장 스키마도, 공급자 SDK도 없다.
원격 의존성은 0개이고, 그 목록이 비어 있는 것 자체가 계약이다.

```
사용자 문장
  → PCC 1회: 대화 답변 · 되물음 · 실행 계획 중 하나
  → 대화·되물음이면 같은 호출의 문장으로 닫는다(도구 0)
  → 실행이면 코어: 순차 실행(앞 결과로 다음 인자 채움 · 빠진 읽기 보정 · 쓰기 앞 승인 · 원장 기록)
  → PCC 1회: 회수한 사실로 최종 답
```

| 산출물 | 무엇 |
|---|---|
| `AgentKernel` | 능력 이름 · 계약 · 수령증 · 원장 · 승인 · 커넥터 · 웹 · 기기 모델 문 |
| `AgentOrchestration` | 차례 한 번의 기계: 단계 · 범위 · 계획 스키마 · 근거 축약 · 문맥 조립 |

## 붙이기

**[INTEGRATION.ko.md](INTEGRATION.ko.md)** 가 정본 안내서다. 복사해 쓰는 템플릿:

```
Examples/Host/project.yml         xcodegen 프로젝트(배포 대상 · 서명 · 패키지 의존성)
Examples/Host/App.entitlements    PCC 엔타이틀먼트
Examples/Host/AgentHostSetup.swift 호스트 배선 한 파일(신원 · 문구 · 설정 · 승인 · 원장)
```

## 검증

iOS 26+ · macOS 27+ 패키지다. 층을 골라 돌린다(iOS 시뮬레이터). macOS에서는 `swift test`도
서지만 층을 가르지 않는다 — 안내서 §1.

```
./Scripts/test.sh          L0   PCC 0 · 기기 모델 0 · 네트워크 0
./Scripts/test.sh local    L1   기기 모델만
./Scripts/test.sh e2e      L3   살아 있는 웹
```

실제 PCC를 지나는 층(L2)은 **엔타이틀먼트를 든 호스트 앱**이 소유한다. 이유와 방법은
안내서 §10에 있다.

## 지금 상태

기록·일정·메일 중심 요청은 호스트 커넥터만 붙으면 돈다. `"웹에서 찾아서 알려줘"`는
아직 답 품질이 부족하고, 그 이유는 측정되어 안내서 §12에 적혀 있다.
